# Information Architecture

## Shared case reset

Every route begins with a compact 20-second case header:

- disputed charge;
- systems required;
- expected policy/approval boundary;
- current replay mode;
- link to claim disclosure.

## Strategy route

1. Business problem and desired outcome
2. Stakeholder and source map
3. Discovery questions and assumptions
4. Architecture and control boundaries
5. Acceptance criteria and phased rollout
6. Canonical case result

## Technical route

1. Source discovery and schema fingerprint
2. Query/tool boundary
3. Evidence normalization and conflicts
4. Deterministic policy versus optional model synthesis
5. Approval state and blocked unauthorized write
6. Idempotent execution and partial failure
7. Trace, tests, and claim evidence

## Operations route

1. Customer-facing state
2. Source/connector/workflow health
3. Failure classification
4. Ownership and escalation
5. Support handoff packet
6. Customer communication and training/adoption

## Product route

1. Business outcome
2. Customer-specific versus reusable components
3. Reference blueprint
4. Product friction evidence
5. Next-customer acceleration
6. Expansion hypotheses and explicit non-claims
